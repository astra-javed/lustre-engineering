# Contributing

Thank you for contributing.

## Engineering principles

- Prefer small, focused changes.
- Explain the reason for a change, not only the commands used.
- Reproduce problems before changing code when practical.
- Record test evidence for fixes and experiments.
- Do not commit passwords, API keys, private keys, tokens, or other secrets.
- Keep lab-specific addresses, credentials, and infrastructure details out of reusable documentation.

## Learning contributions

Labs should normally include:

1. Objective
2. Environment
3. Prerequisites
4. Commands or code
5. Expected observations
6. Failure modes and debugging
7. Validation
8. Cleanup

## Pull requests

Use a focused branch and pull request for substantive changes. Keep the default branch stable and buildable whenever practical.
